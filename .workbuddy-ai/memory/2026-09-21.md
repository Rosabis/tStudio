## 从 Studio-main / ZZZ_Studio-main 移植游戏解包支持到 tStudio（AssetStudio）

用户要求：**只加别人有、我没有的游戏解包办法，自己的不动**。

### 三份代码的关系
- 根目录 `AssetStudio*` = 用户自己的 fork（最全，含 GGZ/GGZV2/OPBR/TsubasaACE/TFTCN/WildRift/HOTD/ROTWGW/TCTUtils/FBAUFile/Oodle 等）

- `ZZZ_Studio-main/` = 别人针对绝区零的 fork（多了 `ZZZ_CB2` / `ZZZ` 两个 Mhy 类型）

### 对比方法（重要，下次直接用）
直接 `diff -rq` 全是无意义差异（两个 fork 保留了 `using System;` 等未使用 using，用户项目删掉了）。
写脚本规范化：去 BOM → 统一换行 → **删空行 / 删 `using xxx;` / 删注释行**，再 diff，才看得到真实差异。
脚本在 `C:\Users\Arthur\AppData\Local\Temp\asdiff\norm.py`（临时目录，可能已被清）。

### 关键约束
`GameManager.Games` 用 **自增 index 做 key**，`GetGame((int)gameType)` 依赖 **enum 顺序 == 插入顺序**。
所以新游戏类型**必须同时追加到列表末尾和 enum 末尾**，不能插中间（否则老游戏的索引全错位）。

### 坑
`BundleFile` 里字段名就叫 `UnityCN`，原本靠 C# "Color Color" 规则直接写 `UnityCN.SetKey(...)`。
把字段类型改成 `IUnityCN` 后该规则失效 → 必须写成 `AssetStudio.UnityCN.SetKey(...)`。

### CI
`.github/workflows/build.yml`：`windows-latest` + `nuget restore` + `msbuild`，编 `AssetStudio_GUI` / `AssetStudio_CLI` 的 `net7.0-windows` 和 `net8.0-windows`。
push 到 `main` 即触发（也有 `workflow_dispatch`）。注意 `AssetStudio.csproj` 是 SDK 风格，**新增的 .cs 会自动 glob 进编译，不用改 csproj**。
`byte.RotateLeft`（UnityCNGuiLongChao 用到）需要 .NET 7+，两个 TFM 都满足。
